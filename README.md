# 🌉 마음다리 (MaeumBridge)

**자가검진 연계형 대학생 정신건강 상담 접근성 개선 서비스 — 교육용 프로토타입**

로그인 없이 PHQ-9(우울)·GAD-7(불안)로 익명 자가검진을 하고, 결과를 3단계로 즉시 안내하고, 상담 대기 현황을 확인해 익명 코드로 예약까지 이어지는 웹 앱입니다.

> ⚠️ 이 앱은 의학적 진단·치료 도구가 아닙니다. 결과는 자가 선별 점수에 따른 안내입니다. 대기 현황과 기관은 시연용 **가상 데이터**입니다.

## 1. 실행 방법 (약 2분)

Python 3.10 이상이 필요합니다. 유료 서비스나 API 키는 필요 없습니다.

```bash
pip install -r requirements.txt
streamlit run app.py          # 브라우저에서 http://localhost:8501 열림
```

검증:

```bash
python -m pytest -q                       # 단위·시나리오 테스트 42개
python validation/run_validation.py       # validation/REPORT.md 생성
```

### 예시 입력 (시연용)
`validation/scenarios.json`의 3개 사례를 그대로 입력하면 1·2·3단계가 각각 나옵니다.

| 사례 | PHQ-9 응답 | GAD-7 응답 | 기대 결과 |
|---|---|---|---|
| S1 | 1,1,1,1,0,1,1,0,0 | 1,1,2,1,0,1,0 | 1단계 자가관리 |
| S2 | 2,2,1,2,1,2,1,1,0 | 2,1,2,1,1,1,1 | 2단계 상담 권고 |
| S3 | 1,2,1,1,1,1,1,0,**1** | 1,1,1,1,0,1,1 | 3단계 + 위기 배너 (9번 문항) |

(0=전혀, 1=며칠, 2=7일 이상, 3=거의 매일)

### 온라인 배포 (심사용 링크)
GitHub에 올린 뒤 [Streamlit Community Cloud](https://streamlit.io/cloud)에서 `app.py`를 지정하면 무료로 링크가 생깁니다. 무료 앱은 한동안 접속이 없으면 잠들므로, 심사 기간에는 하루 한 번 접속해 깨워 두고 **시연 녹화본도 함께 제출**하세요. 클라우드에서는 재시작 시 예약 DB가 초기화됩니다(시연용으로는 문제없음).

## 2. 구조와 데이터 흐름

```
사용자 응답(16문항)
   │  core/screening.py   채점 → 3단계 분류 (+ 9번 문항 안전 규칙)
   ▼
ScreeningResult (점수·단계·근거) ── 응답 원본은 여기서 버림, 저장 안 함
   │  core/guidance.py    단계별 안내문 · 24시간 연락처
   ▼
   │  core/booking.py     data/channels.csv(가상) → 대기 추정 → 정렬
   ▼
익명 예약  → data/bookings.db (코드·채널·시간·우선여부만 저장)
```

| 파일 | 역할 |
|---|---|
| `app.py` | Streamlit 화면 (안내·동의 → 검진 → 결과·대기·예약 → 완료) |
| `core/screening.py` | 문항, 채점, 절단점, 위험도 분류 |
| `core/guidance.py` | 단계별 행동 안내, 위기 연락처, 면책 문구 |
| `core/booking.py` | 영업일 계산, 대기열 모델, 익명 예약(SQLite) |
| `data/channels.csv` | 상담 채널 가상 데이터 |
| `tests/` | pytest 42개 (경계값, 전수 검증, 단조성, 예약, 시나리오) |
| `validation/` | 시나리오 3종, 검증 보고서 생성기 |

## 3. 판단 규칙과 근거

| 조건 (위에서부터 우선) | 단계 | 근거 |
|---|---|---|
| PHQ-9 9번 문항 ≥ 1 | 3 · 우선 연계 + 위기 배너 | 총점이 낮아도 자살 사고 신호는 별도로 다뤄야 함 |
| PHQ-9 ≥ 15 또는 GAD-7 ≥ 15 | 3 · 우선 연계 | PHQ-9 중등도-중증 이상(Kroenke 2001), GAD-7 중증(Spitzer 2006) |
| PHQ-9 ≥ 10 또는 GAD-7 ≥ 10 | 2 · 상담 권고 | 두 척도 모두 10점이 가장 널리 쓰이는 선별 절단점 |
| 그 외 | 1 · 자가관리 | 2주 후 재검진 권장 |

절단점은 `core/screening.py`의 `CUTOFFS` 한 곳에서 바꿀 수 있습니다.

**대기 추정**: 선입선출 대기열에서 `예상 대기(영업일) = ⌈(앞 대기 인원 + 1) ÷ 하루 처리량⌉`. 3단계는 기관별 긴급 슬롯을 따로 써서 계산합니다.

## 4. 검증 결과 요약 (`validation/REPORT.md`)

- PHQ-9 가능한 응답 **262,144가지 전부**에 대해 분류 규칙 불일치 0건
- 9번 문항 규칙이 없었다면 3단계가 되지 않았을 응답 조합이 9번 응답 조합의 56.0% → 안전 규칙이 모두 잡아냄 (응답 조합 기준이며 실제 인원 수가 아님)
- 점수를 올리면 단계가 절대 내려가지 않음(단조성) 확인
- 시나리오 3종 기대 결과와 모두 일치
- 예약: 중복 예약 차단, 조회·취소, DB에 개인정보 열이 없음을 테스트로 확인
- 실제 브라우저에서 Streamlit 화면을 띄워 동의→미응답 경고→9번 문항 시나리오(위기 배너·3단계)→예약→조회·취소까지 클릭으로 확인 (`validation/screenshots/`, `validation/REQUIREMENTS_CHECK.md`)

## 5. 개인정보·안전 설계

- 이름·학번·연락처·로그인 없음. 검진 응답은 결과 계산 직후 세션에서 지움
- 예약 DB 열: `code, channel_id, slot, priority, created_at` 뿐 (테스트로 고정)
- 9번 문항 응답 시 결과 화면 맨 위에 109 안내, 사이드바에 24시간 연락처 상시 노출
- 실제 학생·환자 대상 테스트는 하지 않았음. 진행하려면 지도교수·IRB 사전 검토 필요

## 6. 한계

- 결과는 진단이 아니며, 한국 대학생 집단에서 이 절단점의 정확도를 직접 검증하지 않았음
- 검증은 **규칙이 설계대로 동작하는지**(소프트웨어 검증)이며, 임상적 타당도 검증이 아님
- 대기 데이터·기관은 가상. 실제 효과(대기 단축 등)를 주장할 수 없음
- 자가보고 특성상 과소·과대 응답 가능, 위기 상황의 실시간 개입 기능 없음

## 7. 출처와 이용 조건

- PHQ-9: Kroenke K, Spitzer RL, Williams JBW. *J Gen Intern Med* 2001;16:606–613
- GAD-7: Spitzer RL et al. *Arch Intern Med* 2006;166:1092–1097
- PHQ·GAD-7은 Pfizer 교육 연구비로 개발되었고 "복제·번역·표시·배포에 별도 허가가 필요 없음"으로 공개됨 (www.phqscreeners.com). 한국어 문구는 공식 한국어판과 대조해 사용
- 위기 연락처: 보건복지부 자살예방상담전화 109(2024.1.1. 통합 개통), 정신건강위기상담전화 1577-0199
- 코드: 팀 작성 (생성형 AI 보조 사용, 공모 요강에서 허용)

## 8. 웹 버전 (링크 공유용)

`docs/` 폴더는 같은 기능을 설치 없이 브라우저에서 돌리는 버전입니다(`index.html` + `core.js`). 판정·대기·예약 규칙은 Python `core/`와 같습니다.

- 동일성 검증: `python docs/verify/make_vectors.py . /tmp/v.json && node docs/verify/check_parity.js /tmp/v.json` → 300,208건 비교, 불일치 0건
- 화면 E2E: `python docs/verify/e2e.py docs/index.html shots/` (Playwright + Chrome) → 21개 항목 통과, JS 오류 없음
- 차이점: 예약은 서버 DB가 아니라 **각자 브라우저(localStorage)** 에만 저장됩니다. 그래서 다른 사람의 예약은 보이지 않습니다(시연용).
- 심사용 '예시 응답 채우기' 버튼(S1·S2·S3)이 검진 화면에 있습니다.
